# Замер пруфа блока EVM на арендованном сервере с GPU

Набор, чтобы построить пруф Groth16 блока 3 цепочки Reth (`fixtures/evm_batches/reth/block-3.bin`,
10,3 млн циклов) на Linux-сервере с NVIDIA и проверить его на маке настоящим контрактом в Sandbox.
На маке тот же пруф шёл 1496 с на процессоре при пике следа памяти 28,5 ГБ (PROVING.md). Пруф,
построенный здесь, — замер; основную фикстуру `fixtures/sp1_evm_reth3` он не заменяет.

## Главное: ELF на сервере не пересобирается

Ключ программы (`programVKey`, входит в ключ контракта) зависит от точного ELF, а сборка
побайтно не воспроизводима. Поэтому на сервер едет ELF, собранный на маке
(`6828d42b…fba3` из `fixtures/evm_batches/program.json`), и хост берёт его из файла:
`rollup-evm-host --elf remote-input/rollup-evm-program.elf …`.

- До любой работы хост сверяет sha256 файла с `programElfSha256`, а ключ, который SDK выводит
  из этого ELF на процессоре, — с `programVKey`. Ключ, который выдал сам прувер (на GPU его
  считает `sp1-gpu-server`), сверяется ещё раз перед пруфом. Любое расхождение — отказ с кодом 2.
- `--vkeys` с `--elf` не сочетается: `program.json` пишет только сборка из исходников на маке.
- `build.rs` по-прежнему собирает гостевую программу и запрещает `SP1_SKIP_PROGRAM_BUILD`, так
  что сборка хоста на сервере тоже соберёт ELF. В пруф он не идёт: без `--elf` режимы пруфа
  сверяют вшитый ELF с `program.json`, и чужой ELF получит отказ. Совпал ли здешний ELF с маком,
  записывается в `setup.json` (`serverBuiltElfMatchesMac`) — данные о воспроизводимости сборки.
- В файле пруфа записан sha256 того ELF, которым пруф построен; импортёр на маке сверяет его и
  ключ с `program.json`.

## Где идёт что

| Этап | 48 ГБ (RTX A6000, L40S, A40) | 24 ГБ (RTX 4090) |
|---|---|---|
| исполнение и сжатый пруф | GPU (`sp1-gpu-server`) | GPU |
| shrink, wrap, gnark Groth16 | GPU-сервер одним вызовом (`--prove`) | если не поместится — процессор (`--wrap-groth16`) |

SDK 6.10 с `SP1_PROVER=cuda` отдаёт серверу `sp1-gpu-server` весь пруф одним запросом с
режимом (`sp1-cuda-6.10.0/src/client.rs`): разделить этапы SDK не умеет. Документация SP1
требует для CUDA-прувера от 24 ГБ видеопамяти и compute capability ≥ 8.0, а про память обёртки
говорит только «около 14 ГБ ОЗУ для Groth16»; цифры «40 ГБ» в ней нет. Поместится ли весь пруф в
24 ГБ — неизвестно, поэтому у хоста два пути:

- **один шаг** — `--prove` (Groth16 целиком на сервере GPU);
- **два шага** — `--prove-compressed` (сжатый пруф на GPU, файл bincode SDK) и
  `--wrap-groth16 <файл>` (shrink/wrap штатным `SP1LocalNode::shrink_wrap` и gnark на
  процессоре; сборка свидетеля gnark — перенос `run_groth16` из sp1-prover 6.10.0, `src/wrap.rs`).
  Файл пруфа у второго шага тот же, что у `--prove`: оба пишет одна функция.

`measure.sh` по умолчанию (`auto`) пробует один шаг, а если он упал — два. `both` делает оба
пути подряд (сравнить обёртку на GPU и на процессоре).

Сервер GPU SDK берёт из `~/.sp1/bin/sp1-gpu-server`; если его нет или `--version` не `6.10.0`,
скачивает `https://github.com/succinctlabs/sp1/releases/download/v6.10.0/sp1_gpu_server_v6.10.0_x86_64.tar.gz`
сам и хеш не проверяет (`sp1-cuda-6.10.0/src/server.rs`). `setup.sh` кладёт его заранее и
записывает sha256 архива и бинарника в `setup.json`. Работает только на Linux x86_64.

## Что арендовать (vast.ai)

- **GPU:** 1× RTX A6000, L40S или A40 (48 ГБ) — предпочтительно; либо 1× RTX 4090 (24 ГБ).
  Compute capability ≥ 8.0.
- **Образ:** Ubuntu 22.04 с CUDA 12 (например, шаблон `nvidia/cuda:12.x-devel-ubuntu22.04`
  или PyTorch-шаблон vast на CUDA 12); драйвер, у которого `nvidia-smi` показывает
  «CUDA Version: 12.x» или новее. x86_64.
- **ОЗУ:** от 64 ГБ (процессорная обёртка, исполнение в zkVM; `setup.sh` откажет при < 60 ГБ).
- **CPU:** от 16 ядер (сборка хоста и обёртка на процессоре идут быстрее).
- **Диск:** от 150 ГБ (сборка ~20–30 ГБ, артефакты схемы 8 ГБ, кэши; `setup.sh` откажет при
  свободных < 60 ГБ).
- **Доступ:** SSH (обычно контейнер Docker с root). Docker внутри не нужен: gnark собирается
  нативно (Go).

## Подключение

Ключ SSH — только у вас; в репозиторий ничего не кладётся. Запись в `~/.ssh/config` (значения
из кабинета vast.ai):

```
Host zk-gpu
    HostName <адрес из vast.ai>
    Port <порт из vast.ai>
    User root
    IdentityFile ~/.ssh/<ваш ключ>
```

Скрипты принимают имя этой записи (`zk-gpu`) и сами ни ключей, ни паролей не знают.

## Порядок команд

```bash
# на маке, из корня репозитория (отправляемые файлы должны быть закоммичены)
zkvm-evm/host/remote/push.sh --dry-run        # собрать и проверить набор без отправки
zkvm-evm/host/remote/push.sh zk-gpu           # выложить в ~/ton-zk-rollup на сервере

# на сервере
ssh zk-gpu
tmux new -s zk                                # чтобы обрыв ssh не убил сборку и замер
bash ~/ton-zk-rollup/zkvm-evm/host/remote/setup.sh
bash ~/ton-zk-rollup/zkvm-evm/host/remote/measure.sh            # auto; или onestep | twostep | both

# на маке
zkvm-evm/host/remote/pull.sh zk-gpu           # → .tools/remote-proofs/zk-gpu-<время>/
zkvm-evm/host/remote/verify-local.sh .tools/remote-proofs/zk-gpu-<время>
zkvm-evm/host/remote/cleanup.sh zk-gpu        # и Destroy инстанса в vast.ai
```

`push.sh` везёт только: исходники `zkvm-evm` (lib, host, program, vendor, манифесты,
`Cargo.lock`, `rust-toolchain.toml`) и `zkvm/lib` с `zkvm/Cargo.toml` из git, без `target`;
`fixtures/evm_batches/program.json`; `block-3.bin` и `block-3.json`; `zk/sp1-pins.json`; готовый
ELF и `MANIFEST.sha256` всех файлов. Перед отправкой он сверяет ELF и хеш исходников набора с
`program.json`; на сервере `setup.sh` и `measure.sh` сверяют файлы с манифестом.

`setup.sh` идемпотентен: пакеты apt (`build-essential pkg-config libssl-dev clang cmake
protobuf-compiler libprotobuf-dev git curl python3 time …`), Rust 1.94.0 по
`rust-toolchain.toml`, SP1 v6.10.0 через `sp1up` (версия — из `Cargo.lock`), Go 1.27.4 (как
`.tools/go` на маке; sha256 архива — из списка выпусков go.dev), `sp1-gpu-server`, артефакты схемы
Groth16 v6.1.0 (sha256 `groth16_vk.bin` обязан равняться `verifierHash` из `zk/sp1-pins.json`),
затем `cargo build --release --locked -p rollup-evm-host --features "native-gnark cuda"`.
`protoc` — из apt (3.12.4 на 22.04): `sp1-prover-types` передаёт ему
`--experimental_allow_proto3_optional`.

`measure.sh`: этап `execute` — хост с `--elf` сверяет ELF и ключ и исполняет блок без пруфа;
публичные значения обязаны совпасть с `block-3.json` с мака. Дальше этапы пруфа. Каждый этап — свой
запуск хоста под `/usr/bin/time -v`; раз в секунду пишутся видеопамять (`nvidia-smi`), занятая
ОЗУ и свободное место; сторож останавливает этап, если места меньше `MIN_FREE_GB` (15) или этап
идёт дольше `MAX_STAGE_MINUTES` (120). Итог — `remote-out/proof.json` и `remote-out/measure.json`
(время, пик видеопамяти и ОЗУ по этапам, строки хоста `[этап] …` со временем шагов, сверка пруфа
с `program.json` и отчётом блока).

## Сервис-секвенсор на этом сервере (`prove-job.sh`)

Тот же подготовленный сервер (`push.sh`, `setup.sh`) служит пруверу сервиса:
`sequencer/main.ts run … --prover=remote:zk-gpu` (`sequencer/remoteProver.ts`, подробности —
`sequencer/README.md`, «Прувер на сервере с GPU»). Сервис заходит по ssh и зовёт только
`prove-job.sh` (`check`, `prepare`, `start`, `status`, `cancel`); на сервер он копирует один файл —
вход блока (`remote-jobs/<ключ>/batch.bin`), пруф забирает `scp` и проверяет на маке заново.
Общее с `measure.sh` — `lib.sh` (пути, sha256, переменные шардов для обёртки на процессоре); путь
пруфа тот же: Groth16 целиком на GPU, при неудаче — сжатый на GPU и обёртка на процессоре. Задание
идёт отдельной сессией (`setsid nohup`), обрыв ssh его не гасит; одно задание на сервере. Журналы
задания — `remote-jobs/<ключ>/*.log`. `prove-job.sh` входит в набор `push.sh`; сервис сверяет его
sha256 со своим и отказывает, если на сервере другой — тогда `push.sh zk-gpu` заново (кэш сборки
хоста при этом остаётся).

## Сколько времени

Оценки, не замеры: `push.sh` — секунды; `setup.sh` — 30–60 минут, почти всё — первая сборка
хоста (Reth, SP1, gnark на Go; гостевая программа — ещё несколько минут) и скачивание артефактов
схемы (~6 ГБ); повторный запуск — минуты. `measure.sh` — исполнение 1–2 минуты, пруф — то, что
мы и меряем (на маке на процессоре 25 минут); обёртка на процессоре при двух шагах — минуты.
Почасовая аренда идёт с момента запуска инстанса: арендовать, когда готовы сразу начать.

## Что прислать

Путь каталога, который напечатал `pull.sh` (или сами `measure.json` и `setup.json` оттуда), и
вывод `verify-local.sh`. Если пруф не построился — ещё `stages/*/log.txt` (последние строки
есть и в `measure.json`, поле `tail`).

## Проверка на маке

`verify-local.sh <каталог> [блок=3] [метка=gpu]`:

1. `zk/import-sp1-fixture.mjs … proof.json sp1_evm_reth3_gpu` — ключ программы и ELF из
   `program.json`, публичные значения ровно из `block-3.json`, нулевой нонс, проверка
   спариванием под закреплённым ключом схемы. Метка после номера блока пишет фикстуру рядом с
   `fixtures/sp1_evm_reth3`, не трогая её; каталоги `fixtures/sp1_evm_reth*_*/` git игнорирует.
2. `zk/gen-bn254-groth16-fixture.mjs sp1_evm_reth3_gpu` — подсказки и «лучшая подделка».
3. `REMOTE_PROOF_FIXTURE=sp1_evm_reth3_gpu npx jest tests/RollupEvmRemoteProof.spec.ts`:
   батчи 1–2 по основным пруфам, батч 3 по присланному на настоящем контракте; подделка
   отклоняется кодом 7300. Газ печатается, в `bench/` не пишется.

## Безопасность

- На сервер едут только исходники программы и хоста, ELF, вход и отчёт блока, ключ программы и
  закреплённый ключ схемы — всё это публично (данные батча и так публикуются в TON). Ключей
  секвенсора, мнемоники кошелька, `.env`, токенов GitHub там нет и быть не должно; репозиторий
  не клонируется.
- Поддельный или испорченный пруф ничего не даст: его отвергнут импортёр (спаривание под
  закреплённым ключом) и контракт (код 7300). Худшее, что может сделать сервер, — прислать
  негодный файл или неверные цифры замера.
- Сторонние двоичные файлы на сервере (`sp1-gpu-server`, артефакты схемы, тулчейны) берутся из
  официальных источников; хеш `sp1-gpu-server` нигде не опубликован, поэтому он записывается.
- После замера: `cleanup.sh zk-gpu` удаляет `~/ton-zk-rollup`, `~/.sp1`, Go, Rust и кэши
  (спрашивает подтверждение), затем инстанс уничтожается в vast.ai (Destroy, не Stop).

## Что проверено на маке, а что впервые исполнится на сервере

Проверено: хост собирается с `--features native-gnark` и с `--features "native-gnark cuda"`
(на aarch64 сервер GPU не запустится — SDK паникует, это ожидаемо); `--vkeys` даёт `program.json`
байт в байт прежний, `gen-evm-rollup-key.mjs --check` сходится; `--elf` с верным ELF сверяет
sha256 и ключ (20 с) и исполняет блок 3 с теми же публичными значениями и циклами; с изменённым ELF —
отказ до входа; отказы `SP1_PROVER=mock`, `cuda` без фичи, `cuda` для `--wrap-groth16`,
`--proof-out` без режима и запрещённые сочетания флагов; импорт с меткой и набор
`RollupEvmRemoteProof.spec.ts` (на настоящем пруфе блока 3, импортированном под меткой, и на нём
же под чужим номером блока — набор падает); `bash -n` и shellcheck всех скриптов; `push.sh --dry-run`;
сводки `measure.sh` и `pull.sh` на подставных данных.

Впервые на сервере: всё, что касается GPU (`sp1-gpu-server`, память и время), установка и
сборка на Linux, `--prove-compressed` и `--wrap-groth16` с настоящим пруфом (на маке пруфы не
строятся), сторож и замеры `measure.sh`.
