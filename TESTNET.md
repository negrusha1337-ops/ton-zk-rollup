# TESTNET — прогоны в тестовой сети

> **Нынешняя версия контракта и программ в testnet не запускалась.** Все прогоны ниже — прежних
> версий. В версии прогона 13.11.2026 независимая проверка позже нашла две критичные дыры
> (вывод произвольной суммы через программу выхода и подделку дерева выводов секвенсором) и
> две серьёзные — [REVIEW.md](REVIEW.md). Совпадение газа с Sandbox и успешные транзакции
> этого не показали и показать не могли: прогон проверяет честный сценарий.
>
> Что прогоны всё же установили и что остаётся верным: лимит газа и цены testnet совпали с
> mainnet, версия TVM в сети считает газ так же, как Sandbox, проверка Groth16 на BN254
> помещается в одну транзакцию.

## Верификатор BN254

Цель: развернуть [contracts/bn254_groth16_verifier.tolk](contracts/bn254_groth16_verifier.tolk),
загрузить ключ и проверить настоящий пруф zkVM настоящей транзакцией. Это покажет то, чего
не видно в Sandbox: реальный лимит газа и поведение актуальной версии TVM (Sandbox
эмулирует global version 15, mainnet на момент замера — 17; что в testnet, надо смотреть).

**Только testnet.** Код не проходил аудит, скрипты отказываются работать с mainnet.

## Rollup-контракт на настоящих пруфах SP1

Полный путь rollup-контракта: развёртывание, ключ верификатора v6.1.0 частями, депозит и
принудительные транзакции L2, два батча с Groth16-пруфами SP1, выводы; затем аварийный путь.

```bash
npx blueprint run runRollupTestnet --testnet --mnemonic
npx blueprint run runRollupTestnet --testnet --mnemonic escape   # только аварийный путь: вернуть депозит
node zk/testnet-rollup-report.mjs <адрес rollup-контракта>
npx blueprint run verifyRollupDeployment --testnet --mnemonic <адрес> <chainId> <мин. срок, с> <корень генезиса>
```

Отправляющие скрипты работают только с `--testnet --mnemonic`: с `--custom` сеть нельзя отличить
от mainnet, а кошелёк TON Connect подписывает в своей сети (`wrappers/testnetGuard.ts`).

Первый скрипт идёт от состояния контракта и продолжает с того места, где остановился. Перед
первым сообщением он проверяет, что пруфы SP1 есть и построены для нынешних программ и
нынешнего ключа, и считает, сколько монет нужно на оставшиеся шаги; после фиксации ключа —
что контракт развёрнут ровно с ожидаемыми параметрами и ключами. Вывод или выход он считает
сделанным, только когда заявка погашена в нуллификаторе и выплата дошла получателю
(развёрнутый нуллификатор сам по себе ничего не значит: развернуть его может кто угодно).
Пруфы для нынешних программ построены, так что скрипт готов к запуску — но **после правок
второго, третьего и четвёртого кругов проверки он в сети не запускался ни разу**; его
логика проверена только чтением (рецензенты кругов 3 и 4) и тестами его частей.

Если обычный путь остановился после депозита (батч не прошёл в сети, в очередь вмешался
посторонний, шаг ушёл дважды), депозит уже лежит на контракте. Его возвращает режим `escape`:
он пропускает обычный путь, ждёт срок, замораживает rollup и возвращает необработанные депозиты.

На весь путь, по собственной оценке скрипта, нужно около 2,1 тестовых TON [расчёт по
`wrappers/rollupValues.ts`, не измерено]: 1 TON — депозит (сумма зашита в пруф батча 2),
остальное — суммы сообщений и комиссии кошелька. Аварийный путь ждёт срок заморозки — час:
меньше контракт не допускает. Отчёт (`testnet-rollup-report.mjs`) снимает газ и коды выхода из
сети и отличает выплату от записи долга; с замерами Sandbox он сравнивает, только если те
сняты для тех же программ. Сверка развёртывания ничего не отправляет; адрес, `chainId`,
наименьший приемлемый срок и корень генезиса ей задаёт сам проверяющий — из источника,
которому он доверяет, а не со слов развернувшего ([ARCHITECTURE.md](ARCHITECTURE.md)).

Суммы сообщений — в [wrappers/rollupValues.ts](wrappers/rollupValues.ts), примерно вдвое выше
измеренного расхода газа: всё приложенное сверх газа остаётся на контракте, и вернуть это
нечем. По той же причине на стенде-верификаторе из первого прогона остался 1,05 TON.

## Как повторить прогон верификатора BN254

### Что понадобится

- Кошелёк в testnet с 2 тестовыми TON (их раздаёт бот-кран testnet). Скрипты тратят около
  1,1 TON на суммы сообщений плюс комиссии кошелька.
- Около 26 транзакций: развёртывание, 23 части ключа, фиксация, проверка пруфа.

Подписывать 26 транзакций вручную через TON Connect утомительно, поэтому удобнее отдельный
одноразовый testnet-кошелёк по мнемонике. Его создаёт `node zk/new-testnet-wallet.mjs`
(мнемоника пишется в `.env` и на экран не выводится), баланс показывает
`node zk/testnet-balance.mjs`. Кошельки с фразой из 12 слов режим `--mnemonic` не открывает. Blueprint читает её из файла `.env` (он в
`.gitignore`):

```
WALLET_MNEMONIC="слово1 слово2 ... слово24"
WALLET_VERSION=v5r1
```

Шаблон — в файле `.env.example`. Версия: `v5r1` для кошелька W5, `v4` для v4R2.

Мнемонику основного кошелька сюда не кладите: заведите отдельный кошелёк только для testnet.
В репозиторий `.env` попадать не должен.

### Шаги

1. Развернуть контракт и загрузить ключ (по умолчанию — ключ верификатора SP1 v6):

```bash
npx blueprint run deployBn254Verifier --testnet --mnemonic
```

Скрипт печатает адрес контракта и команду для следующего шага. Если он прервался,
запустите его снова: уже загруженные части пропускаются.

2. Отправить пруф:

```bash
npx blueprint run verifyBn254Proof --testnet --mnemonic <адрес контракта>
```

3. Открыть транзакцию контракта в обозревателе testnet и записать из фазы вычислений
   `gas used` и код выхода.

Для квитанции RISC Zero в обеих командах добавьте в конец `risc0_v3_test_receipt`
(это отдельный контракт со своим ключом).

### Что считать результатом

| Наблюдение | Что это значит |
|---|---|
| Пруф принят, газ близок к 943 702 (SP1) или 948 622 (RISC Zero) | Sandbox и сеть согласны; результат этапа подтверждён |
| Пруф принят, газ заметно другой | Версия TVM тарифицирует иначе — обновить цифры в `ROUTES.md` |
| Код выхода −14 | Не хватило газа: лимит транзакции в testnet ниже либо расход выше. Проверка в одну транзакцию в этой сети не проходит |
| Коды 7002–7010, 7100 | Отказ верификатора. На неизменённой фикстуре это ошибка, которую надо разбирать |

Ожидаемые расходы по замерам в Sandbox: загрузка ключа — около 151 тыс. gas суммарно и
примерно 0,4 МБ данных в 23 сообщениях (самое большое — 23 КБ); проверка пруфа — одно
сообщение на 27 КБ.

### Чего скрипты не делают

- Не проверяют, совпадают ли лимит газа и цены testnet с mainnet. Сверьте конфиг-параметры
  20, 21 и 8 сети перед выводами.
- Не возвращают остаток TON: он остаётся на контракте и идёт на оплату хранения ключа.
- Контракт-стенд не привязывает пруф к состоянию: одно и то же сообщение можно отправить
  повторно, счётчик вырастет. Для rollup'а так нельзя (см. `ARCHITECTURE.md`).
