# ZK-rollup на TON — исследовательский прототип

Цель проекта — rollup с EVM на TON: блоки исполняются вне цепочки, доказываются zkVM, а
контракт на TON проверяет доказательство и хранит корень состояния.

**Что здесь есть сейчас.** Не EVM и не продукт, а работающий прототип нижнего слоя:

- проверка Groth16 на BN254 прямо в TVM (программное спаривание) — так контракт принимает
  пруфы SP1 и RISC Zero без перевода на другую кривую;
- rollup-контракт: батчи с проверкой пруфа, депозиты и выводы TON, очередь с принудительным
  включением, принудительные транзакции L2, публикация данных батчей в TON, аварийный выход;
- программы для zkVM SP1: переход состояния (игрушечный реестр балансов с настоящими
  подписями secp256k1) и аварийный выход.

**Чему здесь нельзя верить.** Код не проходил аудит людьми. Независимые проверки
агентами-рецензентами уже находили в нём критичные дыры — в том числе в версиях, прошедших
testnet. Что найдено, что исправлено и что осталось открытым — [REVIEW.md](REVIEW.md).
Только Sandbox и testnet; настоящих денег здесь быть не должно.

**Настоящие пруфы SP1 нынешних программ построены** (три батча и два аварийных выхода,
13.11.2026), и настоящий контракт принимает их в Sandbox: батчи — 948–951 тыс. gas, выход —
955 тыс. из лимита 1 млн. **В testnet нынешняя версия прошла 13.11.2026** — обычный путь и
аварийный выход, 37 транзакций, газ совпал с Sandbox до единицы
([TESTNET.md](TESTNET.md), контракт
[`EQDqaiKt…tRaB1`](https://testnet.tonviewer.com/EQDqaiKtAYGcQr5a47vm71-YxxAj_sC0U0utOl3RNo5tRaB1)).
Прогон — проверка честного сценария, а не безопасности.

**Спайк EVM (14.11.2026).** Блок EVM, исполненный Reth внутри SP1 (`zkvm-evm/`), доказан пруфом
Groth16 и принят тем же контрактом в Sandbox и в testnet
([`EQBzUp76…sQ1ge2`](https://testnet.tonviewer.com/EQBzUp761GHW3jvEJcaPal6pLn4WpLAZoMqqZLD2JTsQ1ge2)):
948 627 gas. Это демонстрация приёма батча, а не готовый rollup на EVM: принудительные
транзакции не поддержаны, депозитов от настоящего узла нет — см. [REVIEW.md](REVIEW.md), круги 6–9, и
[PROVING.md](PROVING.md), «Спайк EVM».

**Аварийный выход счёта EVM без пруфа (15.11.2026).** Если секвенсор пропал, владелец обычного
счёта L2 забирает баланс сам: присылает контракту заголовок последнего принятого блока,
доказательство счёта (`eth_getProof`) и подпись своим ключом Ethereum — контракт проверяет
дерево Merkle-Patricia и подпись прямо в TVM, без zkVM. 103–144 тыс. gas на настоящих
доказательствах из трёх–пяти узлов (в том числе против блока, принятого по пруфу SP1),
454 тыс. на дереве из десяти полных веток
([ARCHITECTURE.md](ARCHITECTURE.md), «Аварийный выход счёта EVM без пруфа»). В testnet
15.11.2026 выход прошёл на контракте [`EQD06rb5…Kpl3XPy`](https://testnet.tonviewer.com/EQD06rb5PMYFl7JYjFy28ffvPhYtp_TjunTGp2b71Kpl3XPy): 143 859 gas, как в Sandbox ([TESTNET.md](TESTNET.md)).
Токены и контракты L2 так не выходят.

## Быстрый старт

```bash
npm ci
npx blueprint test
cd zkvm && cargo test -p rollup-stf -p rollup-exit -p rollup-native
```

Circom и SP1 для тестов не нужны: ключи и доказательства лежат в `fixtures/`.

## Пересборка ZK-артефактов игрушечных схем

Нужны Rust (для сборки Circom) и Node.js 22+.

```bash
cargo install --git https://github.com/iden3/circom.git --tag v2.2.3 --root .tools circom
npm run zk:build
npm run zk:verifiers
npx blueprint test
```

Trusted setup здесь одноучастниковый и годится только для тестов. Программы zkVM и пруфы
SP1 — в [PROVING.md](PROVING.md).
